V4 — Monetization

This phase covers every place real or test money moves through the platform. It requires an approved vendor (from V3) and Razorpay test-mode credentials configured in the environment.
Before you start: confirm NEXT_PUBLIC_RAZORPAY_KEY_ID and the backend's matching Razorpay test secret are actually set — if they're not, the checkout buttons will show a "not configured" message instead of opening Razorpay, and every payment-dependent test case below will be blocked, not failed. Check this first so you don't waste time misdiagnosing a config gap as a bug.
Known issue — expect this to fail, don't re-log it: the admin store-payments metrics dashboard calls a route that doesn't match what the backend actually returns, so its summary tile shows 0/— even when real orders exist. This is already tracked. Confirm the underlying order data itself is correct elsewhere in the admin UI (orders list) — that's the part that should actually work.
