Manual Test Plan — 5 Phases

A complete, hands-on test pass across the whole platform, ordered by dependency: each phase assumes the one before it works, so start at Phase 1 even if you're tempted to jump to the feature you care about most. Every test case lives in its own phase file below — open one, work top to bottom, check things off as you go. Progress is saved in this browser automatically.

How to use this board

  1. Work the phases in order — V2 assumes you already have a working couple account from V1, V3 assumes a working vendor account, V4 assumes an approved vendor with an active plan, V5 assumes everything before it works.
  2. Each test case has a priority: P0 = core flow, must pass before anything downstream is trustworthy. P1 = real edge case, log a bug if it fails. P2 = minor/cosmetic, note it but don't block on it.
  3. Click a row's status pill to cycle Not started → Pass → Fail → Blocked. Add a one-line note on any Fail so you remember what broke.
  4. When you find a real bug, log it in BugsItemsDoc/ (per PENDING-WORK.md) with the Test ID (e.g. V3-014) so it's traceable back to this board.
  5. A few test cases are marked "Known issue — expect this to fail" for bugs already on record (e.g. the admin store-payments metrics tile). Confirm the symptom matches the known bug; don't re-log it as new.
  6. This board only opens as a local file — progress is saved per-browser via localStorage. If you switch browsers/machines, progress won't follow; that's expected for a local tool.

Test cases are grounded in the actual verified codebase state (Prisma schema, live API routes, both frontend apps) as audited in early September 2026 — not generic QA boilerplate. Where the platform genuinely doesn't have a feature (in-app chat, guest-list manager, social login, AI features), no test case is written for it — testing something that doesn't exist wastes your time, so those are called out instead as "not applicable" inside the relevant phase file.
